# Security

## First run

- The first `migrate` creates a user `admin`. Its password is `ADMIN_PASSWORD` if set, otherwise a random one
  printed once in the container log. There is no admin/admin. Change it after signing in.
- `SECRET_KEY`: generated by the linuxserver base image on first start (kept in `/config`). Set it yourself
  when not using that image.

## Behind a reverse proxy

| Variable | Set it to |
|---|---|
| `ALLOWED_HOSTS` | Your hostnames, comma-separated (default `*` accepts any Host header) |
| `CSRF_TRUSTED_ORIGINS` | Full origins people use, e.g. `https://pets.example.com` |
| `SECURE_PROXY_SSL_HEADER` | `True` when the proxy terminates HTTPS and sends `X-Forwarded-Proto` |
| `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE` | `True` when the site is only reached over HTTPS |

## Who can do what

- Everything belongs to a household; pages and the API only ever show the signed-in user's household
  (tested in `pets/tests/test_security.py`).
- Household roles: owners and members log and change setup, read-only members only look, owners manage
  household settings and members' roles.
- Only site admins (superusers) create accounts and add people to households.
- Baby Buddy's own API (`/api/children/` and so on) is off unless baby mode is on. The pet API is `/api/v1/`.
- Logins are rate-limited by django-axes (from Baby Buddy).
